Optional 4A · n-step SARSA

Three blocks, 30 minutes each. Reading: Sutton & Barto (2018), Chapter 7 §§7.1–7.2. Extension: Chapter 12 eligibility traces and TD(λ).

Theory / Plain English

Maintain an n-transition window, choose actions every step, and update a state/action n steps behind. n=1 is SARSA; at episode end the remaining tail has an MC return.

G = r1 + γr2 + … + γ^(n−1)rn + γ^n Q(s_next,a_next)

Code

Run pixi run python -m reference.nstep. In the session 4 SARSA loop, replace each immediate update with a FIFO trajectory window and this target. Flush all pending updates at episode end; use the actual next action at the bootstrap state. The bundled calculator is complete; the n-step agent integration is an exercise.

Alternatives

Compare n=1,2,4,8 and full returns. Multi-step off-policy control needs additional care; do not simply substitute a max and call it an unbiased on-policy method. Eligibility traces mix horizons; TD(λ) deserves a separate workshop.

Systems / experiments

Log window size and pending updates. On CliffWalking compare equal environment-step budgets and five seeds. During the final 30 minutes, inspect a terminal tail and draw the buffer lifecycle. Between sessions, compare variance and final greedy evaluation.

Quiz: does n-step delay action choice?

No. Actions may be selected each environment step; the target aggregates rewards over several steps.

Facilitator checkpoint

First block: hand-calculate n=1 and n=3. Second: calculator tests then FIFO integration. Third: terminal flush audit and n sweep plan. Pass when every transition is updated once per eligible window, including the terminal tail.
